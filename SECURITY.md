# Security Policy

## Reporting a Vulnerability

If you discover a potential security issue in this project, or believe you may have found a security vulnerability, please report it privately to the ByteDance security team through the [ByteDance Security Center](https://security.bytedance.com/src/) or by email at [src@bytedance.com](mailto:src@bytedance.com).

Please do not create public GitHub Issues for security vulnerabilities.

When reporting a vulnerability, include as much of the following information as possible:

- A description of the issue and its potential impact.
- Affected versions, branches, commits, or file paths.
- Steps to reproduce the issue.
- Proof-of-concept code or exploit details, if available.
- Any known mitigations or suggested fixes.
- Whether the vulnerability has already been disclosed publicly or reported elsewhere.

## Vulnerability Handling and Disclosure

The ByteDance security team will assess reported vulnerabilities based on the Common Vulnerability Scoring System (CVSS 3.1). The team will keep you updated on key progress and may request additional information or guidance from you during triage and remediation.

To protect users, please do not publish or share vulnerability details, exploit information, or user-related data in any public forum until the vulnerability has been remediated and affected users have been notified when necessary. The time required for remediation depends on the severity of the vulnerability and the scope of its impact.

If you, your company, or your security team plan to publish a security advisory, blog post, or other public disclosure, please contact us through the channels above before publication so that we can coordinate the information to disclose and the disclosure timeline.
